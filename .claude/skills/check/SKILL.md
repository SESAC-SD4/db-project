# /check — 기준표로 판정

## 1. 무엇을 판정할지

팀 폴더(`teams/<팀이름>/`)에서 찾는다.

- `schema.sql`에 `CREATE TABLE`이 있으면 → `schema.sql`을 판정하고, ERD와 다른 곳도 찾는다
- 없으면 → ERD를 판정한다. `erd.drawio.png`를 이미지로 읽는다(Mermaid로 그린 팀은 `erd.md`). 글씨를 읽기 어려우면 읽은 표 · 칸 목록을 보여 주고 맞는지 묻는다. 파일이 없으면 draw.io에서 PNG로 내보내라고 안내한다(`docs/erd-guide.md`)
- `README.md`의 요구사항도 함께 읽는다(기준표 6 · 8번에 필요)
- 기능 추가 중이면(`README.md`의 "기능 백로그"에 "진행 중"이 있으면) 그 기능의 요구사항 문장이 표에 담겼는지도 본다

## 2. 판정 표

`docs/checklist.md`의 1~8번을 하나씩 본다. 이 모양으로 보여 준다.

| # | 기준 | 결과 | 근거 |
| ---: | --- | :---: | --- |
| 1 | 칸 하나에 값 하나 | ✅ | 모든 칸이 값 하나 |
| 2 | N:M마다 연결 표 | ❌ | `posts`와 `tags` |

- 결과는 ✅ · ❌ · ❔ 셋 중 하나. ❔는 ERD만으로 알 수 없어 팀에게 물어야 하는 것
- 근거에는 **어느 표, 어느 칸**인지 적는다. `schema.sql`이면 줄 번호도
- ❌에는 고친 모양을 쓰지 않는다

**7번 `ON DELETE`**

- ERD를 판정할 때: ERD에는 보통 적을 곳이 없다 → ❔로 두고 "FK마다 가리키는 행이 지워지면 어떻게 할지 정했나요?"를 물을 수 있다
- `schema.sql`을 판정할 때: `ON DELETE`가 없는 FK를 ✅로 넘기지 않는다 → ❔ "이 FK는 지울 수 없게 막기로 정한 건가요?"
- 모든 FK에 같은 것(예: 전부 `CASCADE`)을 붙였으면 → ❔ FK 하나를 골라 "이게 지워지면 이것도 지워지는 게 맞나요?"를 묻는다

## 3. 고칠 곳

❌ · ❔가 있으면 **가장 중요한 하나만** 골라 질문을 하나 던진다.

- 예: "게시물 하나에 태그가 여럿, 태그 하나도 게시물 여럿에 붙죠. 이 둘을 잇는 표가 어디 있나요?"

이 질문은 `/hint`의 단계가 아니다. 팀이 고치고 다시 `/check`를 부르면 처음부터 다시 본다.

## 4. 모두 ✅이면

무엇이 잘 됐는지 한 줄로 말하고 다음 단계를 알려 준다.

- ERD를 판정했으면 → `schema.sql` 쓰기(`docs/rules.md`)
- `schema.sql`을 판정했으면 → psql에서 실행해 보고, 에러 없이 끝나면 `/data`
