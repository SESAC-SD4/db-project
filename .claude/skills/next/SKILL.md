# /next — 기능 하나 더하기

## 1. 지금 상태

`teams/<팀이름>/README.md`의 "기능 백로그" · "변경 기록"과 `schema.sql` · `queries.sql`을 읽는다.

- 기본(ERD · `schema.sql` · `data.sql` · 기능 쿼리 3개)이 아직이면 기본부터 끝내라고 알려 주고 멈춘다
- "진행 중"인 기능이 있으면 고리의 어디까지 했는지 확인하고 다음 할 일을 알려 준다. 새 기능은 고르지 않는다

## 2. 기능 고르기

- **백로그에 팀이 낸 기능이 있으면** 그 목록을 보여 주고 하나를 고르게 한다
- **백로그가 비었거나 팀이 고르지 못하면** 후보 셋을 요구사항 문장으로 제안한다. 크기를 섞는다(작은 것 · 중간 · 큰 것)
  - 예시 주제면 `docs/cards.md`에서 아직 하지 않은 것으로
  - 팀 아이디어면 이 서비스에 실제로 나올 법한 기능 요청으로 새로 만든다
  - 후보 문장은 "누가 · 무엇에 · 몇 번"이 분명하게 쓴다(예: "회원 한 명은 한 모임에 후기를 한 번만 남긴다")
- **어느 표가 바뀔지, 어느 쿼리 결과가 달라질지는 말하지 않는다.** 그것을 찾는 것이 팀의 일이다

## 3. 칠 사람

기능을 고르면 **고리 순서를 보여 주기 전에** 반드시 묻는다. 차례를 정해 주지 않는다.

> 이번엔 누가 키보드를 잡나요? (지난 바퀴와 다른 사람)

팀이 답하면 `README.md` "기능 백로그"에서 고른 기능을 "진행 중 — <칠 사람>"으로 표시하고, "요구사항"에 그 기능의 문장을 번호를 이어서 더한다(팀의 말로).

## 4. 고리 순서

칠 사람이 정해진 뒤 이 순서를 보여 준다.

1. ERD 고치기(draw.io → `erd.drawio.png`) → `/check`
2. `schema.sql` 고치기 → `/check`
3. `/data` — 바뀐 표에 맞게 `data.sql` 고치기
4. 다시 만들고 이전 쿼리 전부 다시 돌리기: `\i schema.sql` → `\i data.sql` → `\i queries.sql`
5. 영향받은 쿼리 고치기(기능 쿼리 개수로 세지 않는다) · 이 기능으로 새로 할 수 있게 된 것 하나를 `/ask`로
6. `README.md` "변경 기록"에 한 줄
7. 커밋 · push: `git add teams/<팀이름>` → `git commit -m "기능: <기능> (<친 사람>)"` → `git push`

마지막에 첫 질문 하나를 던진다.

> **이 기능을 담으려면 지금 ERD에서 무엇이 바뀌어야 할까요?**

## 5. 고리가 끝나면

팀이 4번까지 마치고 돌아오면 `README.md` "변경 기록"에 이 칸을 채우게 한다(팀이 말하고 Claude가 적는다).

| 기능 | 바뀐 표 | 영향받은 쿼리 | 처음부터 알았다면 |
| --- | --- | --- | --- |

- 영향받은 쿼리가 없으면 "없음"과 함께 **왜 이번엔 괜찮았는지** 한 줄을 적게 한다
- "진행 중" 표시를 "완료"로 바꾼다
