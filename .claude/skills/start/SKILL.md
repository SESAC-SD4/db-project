# /start — 주제 · 요구사항 · 기능 백로그

## 1. 팀 폴더와 팀원

`teams/` 아래에서 `_template`이 아닌 폴더를 찾는다.

- 없으면 팀 이름을 묻고, 팀이 터미널에서 직접 만들게 한다: `cp -r teams/_template teams/<팀이름>`
- 둘 이상이면 어느 폴더인지 묻는다
- 팀원 이름을 묻고 `README.md`의 팀 이름 · 팀원을 채운다. `README.md`의 `<팀이름>`도 실제 폴더 이름으로 바꾼다

## 2. 주제

`docs/topics.md`의 세 주제(인스타그램 · 도서관 대출 · 배달 앱)를 한 줄씩 소개하고, 자기 아이디어도 된다고 말한다.

자기 아이디어면 이 조건을 확인한다. 안 맞으면 어떻게 넓히거나 줄일지 묻는다.

- 표가 4~6개쯤 나올 크기
- "하나가 여럿을 가진다"(1:N)가 하나 이상
- "서로 여럿"(N:M)이 하나 이상

## 3. 요구사항 인터뷰

한 번에 질문 하나씩, 이 순서로 묻는다. 질문마다 예는 하나만 든다.

1. 이 서비스를 쓰는 사람은 누구인가요?
2. 그 사람이 하는 행동을 세 개에서 다섯 개 말해 보세요
3. 행동마다 무엇을 남겨야 하나요? (이름 · 날짜 · 가격처럼)
4. 이 둘은 하나가 여럿을 가지나요, 서로 여럿인가요? (팀이 말한 것 중 두 개를 골라 묻는다)
5. 같은 것이 두 번 생길 수 있나요? (팀의 주제에서 예 하나 — 예: 같은 게시물에 좋아요 두 번) — **반드시 묻는다**

예시 주제를 골랐으면 `docs/topics.md`의 문장을 출발점으로 쓴다. 팀이 "그냥 다 넣어 주세요"라고 해도 **한꺼번에 옮기지 않는다.** 문장 하나씩 보여 주며 넣을지, 바꿀지, 뺄지 묻는다. 그 사이에 4 · 5번 질문을 끼워 넣는다.

## 4. 적기

팀이 말한 내용을 **팀의 말 그대로** `teams/<팀이름>/README.md`의 "요구사항"에 번호 문장으로 적는다. 표 이름이나 칸 이름은 적지 않는다.

## 5. 기능 백로그

팀원 한 사람씩 "나중에 이 서비스에 넣고 싶은 기능"을 하나씩 말하게 한다. `README.md`의 "기능 백로그"에 적는다(지금은 설계하지 않는다). 기본을 마친 뒤 `/next`에서 여기서 하나씩 꺼낸다.

적은 뒤 다음 단계를 알려 주고 **질문 없이 끝낸다.** 팀이 "그리러 갈게요"라고 하면 더 묻지 않는다.
